# Hero Body Prototype — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one gas giant — real world-space geometry, lit by a real sector star, hundreds of belt strokes, bloom-driven limb, large enough to dominate the frame — as a visible prototype the owner judges before any further stage of [docs/environment.md](../../environment.md) is planned.

**Architecture:** A body is two mechanisms, per spec §5.1. A `VectorObject` **shell** writes depth so the body occludes the starfield and owns the silhouette; all **surface detail** goes through a `TraceBuffer` regenerated every frame with per-stroke intensity computed from a light direction — the same mechanism the comet's plume already uses at 779 lit, moving segments a frame. That split is what makes rotation free and lighting a multiply.

**Tech Stack:** TypeScript, three.js, Vite. Tests are `tools/playtest.mjs` (Playwright against a live dev server); this project has no unit-test runner and adding one is out of scope.

## Global Constraints

Copied from `CLAUDE.md` and `docs/environment.md`; every task inherits these.

- **`npm run typecheck` before every commit.** There is no lint step.
- **Occluded geometry, not pure wireframe** — glowing edges over near-void opaque faces, via `VectorObject`.
- **Transient strokes go through `TraceBuffer`** — never new objects and materials per stroke.
- **Time-based, not frame-based.** Rotation and drift use `dt`.
- **`src/chart/` must not import `three` or touch the DOM.** Nothing here touches `src/chart/`.
- **Colour is information — but bodies are exempt** (spec §4.1). A body may carry saturated hue and full luminance. It may **not** pulse, blink or flare: behaviour disambiguates where hue no longer does.
- **The far plane stays at 2000 and the leash stays** (spec §4.2). Do not touch `Stage.ts`'s camera.
- **Merged geometry over many objects** (spec §4.3) — each `VectorObject` is a draw call.
- **No new key binding.** The control surface is full; localhost gets a `window.__sky`-style hook.
- **No photoreal** (spec §4.5). The target is stylised: glow, density, silhouette.
- **Existing suites must stay green:** `npm run playtest` (90 assertions), `npm run typecheck`, `npm run campaigntest`, `npm run audiotest`.

## Existing API this plan builds on

- `VectorObject` — `new VectorObject(geometry, { color, linewidth })`, `.group`, `.addTo(parent)`, `.setMode(mode)`, `.setColor(c)`, `.setIntensity(n)`, `.dispose()`. Bakes vertex colours at construction; **cannot** express time-varying brightness.
- `TraceBuffer` — `.begin()`, `.push(ax,ay,az,bx,by,bz,color,intensity)`, `.end()`. `MAX_SEGMENTS = 5000`, shared game-wide. Driven from `src/main.ts:910-934`.
- `makeRng(seed)` from `src/chart/rng.js` — deterministic; `planPlanet` in `src/render/Planet.ts` is the house pattern for per-sector seeding.
- Scene fog is `45..260` (`Stage.ts:49`); distant objects set `fog: false` and manage their own falloff, as `Planet.ts` and the comet do.

### Task 2: The sector's star

Spec §3.1 — the largest lever, and everything downstream reads it.

**Files:**
- Create: `src/render/light.ts`

**Interfaces:**
- Produces:
  - `export interface SectorLight { position: Vector3; colour: Color }`
  - `export function planLight(seed: number, sector: number): SectorLight` — seeded, deterministic, a different hash mix from `planPlanet`'s and the comet's so the three are uncorrelated.
  - `export function shadeAt(light: SectorLight, point: Vector3, normal: Vector3): number` — returns 0–1, the brightness multiplier for a stroke at `point` with surface `normal`. Lambertian with a lifted floor so the unlit side is dim rather than black; a body that disappears on its dark side reads as a hole, not a sphere.

- [ ] **Step 1: Write the module**

Keep it pure and small — no three.js scene objects, only maths on `Vector3`/`Color`. This is the one function every body's renderer calls, so it must be cheap: it runs per stroke per frame.

Document the floor constant with what it trades: too low and the body loses its silhouette against black, too high and there is no terminator to see.

- [ ] **Step 2: Expose it for testing and assert it**

Add to `main.ts`'s localhost probe block: `window.__light = { planLight, shadeAt }`. Then in `tools/playtest.mjs`, near the comet's own pure-function assertions at the top of the file:

```js
const lit = await page.evaluate(async () => {
  const { planLight, shadeAt } = window.__light;
  const l = planLight(12345, 7);
  const at = { x: 0, y: 0, z: 0 };
  const toward = { x: l.position.x, y: l.position.y, z: l.position.z };
  const len = Math.hypot(toward.x, toward.y, toward.z);
  const facing = { x: toward.x / len, y: toward.y / len, z: toward.z / len };
  const away = { x: -facing.x, y: -facing.y, z: -facing.z };
  return {
    facing: shadeAt(l, at, facing),
    away: shadeAt(l, at, away),
    same: planLight(12345, 7).position.x === l.position.x,
    other: planLight(12345, 8).position.x !== l.position.x,
  };
});
check("a surface facing the star is bright", lit.facing > 0.8, `v=${lit.facing}`);
check("...and one facing away is dim but not black", lit.away > 0 && lit.away < 0.25, `v=${lit.away}`);
check("the sector's star is seeded", lit.same, "same seed and sector differ");
check("...and differs between sectors", lit.other, "two sectors share a star position");
```

Run: `npm run typecheck && npm run playtest`
Expected: typecheck clean; the four new assertions pass and all 90 pre-existing ones still pass.

### Task 3: The hero gas giant

The prototype itself. Everything before this was scaffolding.

**Files:**
- Create: `src/render/GasGiant.ts`
- Modify: `src/main.ts` — construct one, add it to the scene, draw it into `skyTrace`, expose `window.__giant`

**Interfaces:**
- Consumes: `SectorLight`, `shadeAt`, `planLight` (Task 2); `skyTrace` (Task 1).
- Produces: `export class GasGiant` with `readonly object: Group`, `show(seed, sector, light)`, `update(dt)`, `draw(trace)`, `setMode(...)`, `clear()`; and `export const GIANT` holding every constant.

- [ ] **Step 1: The shell**

A `SphereGeometry` through `VectorObject`, uniform brightness, `renderOrder` below the ships so it sits behind them. Its only jobs are to **write depth** (so it eats the starfield — spec §3.4) and give the silhouette. Low segment count: this is barely seen, the detail sits on top.

- [ ] **Step 2: The belts — this is the bet**

Per spec §3.3, hundreds of arcs, not eight stripes. For each belt: a latitude, a slight tilt, a width, and a brightness; walk it in segments, and for each segment compute the surface normal, call `shadeAt`, and push into `skyTrace` at that intensity. Add turbulence — a per-belt sinusoidal wobble in latitude that shears with longitude — so the bands are weather rather than hoops, plus one storm oval.

Rotation is a longitude offset advanced by `dt`; because the strokes are rebuilt every frame, this is free and the lit side moves correctly.

**Only draw the near hemisphere.** A sphere's far side would otherwise draw through it — the shell writes depth, but these strokes are `TraceBuffer` segments and cheaper to cull by normal than to depth-test.

- [ ] **Step 3: The limb halo — spec §3.2**

A ring of strokes just outside the silhouette, densest at the edge and brightest where the star is, so bloom turns it into atmosphere. This is the mechanism behind the word *phosphorescent*; it is a brightness distribution, not a colour.

- [ ] **Step 4: Scale it — spec §3.5**

Size and distance chosen so the body **dominates the frame**: roughly a third of the view, limb curving out of shot. Inside the 2000 far plane, fog-exempt, leashed like `Planet.ts` so you can never fly into it.

- [ ] **Step 5: Look at it**

A dev server may be running on 127.0.0.1:5173 — check with `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5173/` and start one if not. **Never `pkill` vite.**

Screenshot with the **post chain on** — bloom is load-bearing here and a post-disabled shot cannot show whether Step 3 worked. Capture at least: the body dominating the frame, the terminator visible, and the same body from a different angle to prove the lighting is positional rather than baked.

Judge it against the spec's own bar: does this read as *weather on a sphere lit by a star*, or as a wireframe ball with stripes? Say which, plainly. **A negative answer here is the most valuable output this plan can produce** — stage 1 exists to test the bet cheaply.

- [ ] **Step 6: Measure the budget**

Count segments pushed per frame and draw calls added. Record both in the report; they go into `docs/todo.md` per spec §4.4.

- [ ] **Step 7: Assertions**

```js
const giant = await page.evaluate(() => {
  const g = window.__giant;
  let n = 0;
  g.draw({ push: () => n++ });
  const before = g.longitude;
  g.update(1.0);
  return { segments: n, rotated: g.longitude !== before, hasShell: !!g.object.children.length };
});
check("the giant draws a dense field of strokes", giant.segments > 400, `${giant.segments} segments`);
check("...within the scenery buffer's budget", giant.segments < 20000, `${giant.segments} of 20000`);
check("...and rotates on its axis", giant.rotated, "longitude did not advance");
check("...over a shell that can occlude", giant.hasShell, "no shell in the group");
```

- [ ] **Step 8: Run everything and commit**

Run: `npm run typecheck && npm run playtest && npm run campaigntest && npm run audiotest`
