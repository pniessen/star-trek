# The Comet — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the comet from [docs/comet.md](../../comet.md) — a nucleus and an ion tail inside which no instrument works, placed both as a seeded sector fixture and as a rare wanderer.

**Architecture:** One new module `src/game/comet.ts` owning the object, the tail-volume test and both schedulers, mirroring `loom.ts`. Its effect reaches the rest of the game through exactly **one new number** — `Hostile.interference`, set by `Session` each frame — which three existing systems already know how to consume. Rendering is a per-frame stroke field through `TraceBuffer` plus a small occluded nucleus, following `Planet.ts`.

**Tech Stack:** TypeScript, three.js, Vite. Tests are `tools/playtest.mjs` (Playwright, asserts against a live dev server) — this project has no unit-test runner and adding one is out of scope.

## Global Constraints

Copied from `CLAUDE.md` and `docs/comet.md`; every task inherits these.

- **`npm run typecheck` before every commit.** There is no lint step.
- **Transient strokes go through `TraceBuffer`** — never new objects and materials.
- **Occluded geometry** for solid bodies: glowing edges over near-void opaque faces, via `VectorObject`.
- **Colour is information.** The comet may not take an information hue. Pale, desaturated, low-luminance only — strictly below every `PALETTE` entry in both saturation and luminance.
- **Time-based, not frame-based.** Everything that drifts or drains uses `dt`.
- **`src/chart/` must not import `three` or touch the DOM.** Nothing in this plan touches `src/chart/`.
- **No key binding.** Localhost gets `window.__comet.seed()`; the control surface is full.
- **Behind `encounters.comet`**, defaulting `true`, added to the existing object in `loom.ts`.
- **The scanner may never show anything false.** Degradation happens only through the existing unresolved-return grammar.
- **`TraceBuffer` holds 5000 segments total**, shared with beams, debris, corridor guides and the Loom. The tail's budget is `COMET.strokes` and must be a small fraction of that.

  - `export function interferenceAt(plan: CometPlan | null, x: number, z: number): number` — 0 outside, rising to 1 on the axis.
  - `export function planFixture(seed: number, sector: number, sunAzimuth: number | null): CometPlan | null`
  - `export function planWanderer(around: Vector3, sunAzimuth: number | null, rng: () => number): CometPlan`

- [ ] **Step 1: Write the constants and the volume test**

`interferenceAt` is a 2D test on the XZ plane and that is deliberate — the slab is ±14 units against a tail hundreds long, so a tail that ignored height would be indistinguishable from one that did not, and the cheaper honest version wins. Record that in the docblock.

```ts
export function interferenceAt(plan: CometPlan | null, x: number, z: number): number {
  if (!plan) return 0;
  const vx = x - plan.nucleus.x;
  const vz = z - plan.nucleus.z;
  // Along the tail. Negative is sunward of the nucleus, where there is no tail.
  const t = vx * plan.direction.x + vz * plan.direction.z;
  if (t < -plan.nucleusRadius || t > plan.length) return 0;

  const px = vx - plan.direction.x * t;
  const pz = vz - plan.direction.z * t;
  const perp = Math.hypot(px, pz);

  // The coma: a sphere of interference around the nucleus itself, so the head is
  // not a hole in the middle of its own tail.
  if (t < 0) return perp < plan.nucleusRadius ? 1 : 0;

  const along = t / plan.length;
  const radius = plan.nearRadius + (plan.farRadius - plan.nearRadius) * along;
  if (perp > radius) return 0;

  // Falls off toward the edge and toward the far end, so the boundary is a
  // gradient rather than a wall the player can stand one unit outside of.
  const across = 1 - perp / radius;
  const fade = 1 - Math.max(0, (along - COMET.solidFraction) / (1 - COMET.solidFraction));
  return Math.min(1, across * Math.max(COMET.tipFloor, fade) * COMET.strength);
}
```

- [ ] **Step 1: Build the nucleus as occluded geometry**

An `IcosahedronGeometry` with jittered vertices — irregular, because a perfectly round comet reads as a moon. Through `VectorObject` so it occludes the tail behind it, which is the argument `Planet.ts` records for why the ringed planet stopped being a picture.

- [ ] **Step 2: Build the tail as a drifting particle field**

`COMET.strokes` particles, each holding `along` (0–1), `angle`, `radial` (0–1). Each frame, advance `along` by `COMET.flow * dt / length` and wrap. Draw each as a short segment along the tail axis, brightness falling with `along` and with `radial`.

Seeded from the plan so the same comet looks the same twice, and **regenerated, never accumulated** — this is a `TraceBuffer` field, so `draw` pushes and nothing persists.

- [ ] **Step 3: Colour**

Pale desaturated ice-blue, defined locally in `comet.ts` rather than added to `PALETTE`, because `PALETTE` is the information vocabulary and this is explicitly not part of it. Assert by eye against `PALETTE.traceDim` — the tail must read as dimmer and less saturated than structure.

### Task 3: `Hostile.interference` and its three consumers

The one change that makes the rule real. **This is the task most likely to go wrong**, for the reason recorded in `docs/comet.md` §7: `cloak` cannot be reused, because it also gates `hidden()` and `shape.group.visible`, so driving it up for interference would make hostiles invisible and invulnerable inside the tail — the exact inverse of the intent.

**Files:**
- Modify: `src/game/hostiles.ts`
- Modify: `src/hud/scanner.ts:129,157`

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces: `Hostile.interference: number` — 0–1, set externally each frame by `Session`, reset to 0 in `Hostile.spawn`.

- [ ] **Step 1: Add the field**

```ts
/**
 * How badly this contact's instruments are being jammed, 0–1. Set each frame by
 * `Session` from the comet; not owned here, because the comet is a thing in the
 * sector and a hostile has no idea it is in one.
 *
 * Deliberately *not* folded into `cloak`. That field gates `hidden()` and
 * `shape.group.visible`, so raising it for jamming would make a hostile
 * invisible and unhittable inside the tail — the opposite of the intent, which
 * is that the tail is where you can finally *see* things.
 */
interference = 0;
```

- [ ] **Step 2: Cloak suppression**

In `updateCloak`, before anything else: while `interference > COMET.stripAt`, drive `cloak` down at `dt / spec.wind` and refuse to re-veil. A Shroud in the tail is a Shroud you can shoot.

- [ ] **Step 3: Fire-control suppression**

The fire gate at `hostiles.ts` currently reads `distance < this.spec.fireRange`. Interpolate the range down toward a short visual range:

```ts
const reach = MathUtils.lerp(this.spec.fireRange, COMET.visualRange, this.interference);
if (this.cooldown <= 0 && !this.hidden && distance < reach && aimError < 0.4) {
```

This is **fire-control suppression, not navigation** — see `docs/comet.md` §5. The hostile still flies its normal approach; it simply may not shoot from outside visual range.

- [ ] **Step 4: Scanner degradation**

`hud/scanner.ts:129` currently paints a ghost when `hostile.cloak > 0.05`. Both the condition and the spread take the larger of the two sources:

```ts
const vague = Math.max(hostile.cloak, hostile.interference);
if (vague > 0.05) this.paintGhost(hostile, range, vague);
```

and inside `paintGhost`, `spread` multiplies by `vague` instead of `hostile.cloak`. The drawn circle still always contains the truth, so the scanner is still not lying.

Run: `npm run typecheck && npm run playtest`
Expected: all existing assertions still pass — with no comet in play `interference` is 0 everywhere and every path above is the old path exactly.

- [ ] **Step 1: Construct and hand it in**

`main.ts` builds the `Comet` with a nucleus factory the way it builds the `Loom` with a spinner factory, adds `comet.object` to the scene, and passes it to `Session`.

- [ ] **Step 2: Per-frame interference and the drain**

In `Session.update`, once per frame:

```ts
const here = interferenceAt(this.comet.plan, player.position.x, player.position.z);
for (const hostile of this.fleet.hostiles) {
  hostile.interference = Math.max(
    here,
    interferenceAt(this.comet.plan, hostile.position.x, hostile.position.z),
  );
}
if (here > 0) player.energy = Math.max(0, player.energy - COMET.drain * here * dt);
```

`max` of the two positions is what "nothing locks across the boundary" means: either end being jammed is enough.
